# Credit Card Fraud Detection and Risk Analysis (ML)

A machine learning project that detects fraudulent credit card transactions and scores the risk of each transaction, so suspicious activity can be flagged for review.

> **Status:** Complete. Data generation, EDA, preprocessing, training, evaluation and risk scoring are all done. The data is synthetic, so the scores are much higher than real-world fraud detection would give.

## Overview

Credit card fraud is rare compared to genuine transactions, which makes it a highly imbalanced classification problem. This project aims to:

- Explore and understand transaction data (EDA)
- Handle class imbalance (e.g. SMOTE, undersampling, class weights)
- Train and compare classification models
- Evaluate with metrics suited to imbalanced data
- Convert model output into a risk score / risk category

## Approach

1. **Data collection** - synthetic transactions generated by `src/generate_data.py`
2. **Preprocessing** - feature engineering, stratified train/test split, scaling with train mean and std
3. **Imbalance handling** - oversampling of fraud rows in the train set only
4. **Modeling** - Logistic Regression, Decision Tree and Random Forest
5. **Evaluation** - Precision, Recall, F1-score, ROC-AUC and PR-AUC (accuracy alone is misleading here)
6. **Risk analysis** - map predicted fraud probability to Low / Medium / High risk

## Dataset

The dataset is generated by `src/generate_data.py`. Each row is one transaction.

| Column | Meaning |
|---|---|
| `amount` | Transaction amount in rupees |
| `hour` | Hour of the day (0-23) |
| `txn_count_1h` | Number of transactions by the card in the last hour |
| `avg_spending` | Average amount the card usually spends |
| `new_location` | 1 if the transaction is from a new location, else 0 |
| `txn_type` | `online`, `pos` or `atm` |
| `is_fraud` | Target: 1 = fraud, 0 = normal |

Normal transactions are usually a few hundred rupees during the day. Fraud
transactions are large, late at night, come in quick bursts and from a new place.

## Note on the data

The dataset is synthetic. Fraud rows are generated to look very different from normal rows (big amounts, late night, many transactions in an hour), so models score close to 100% here. These numbers will not match real-world fraud detection.

## Predicting risk

`src/predict.py` takes one raw transaction and returns the fraud probability and a risk level.

```python
# run from the project root: python src/predict.py
from predict import predict_transaction

predict_transaction({"amount": 35000, "hour": 2, "txn_count_1h": 6,
                     "avg_spending": 600, "new_location": 1, "txn_type": "online"})
# {'fraud_probability': 1.0, 'risk_level': 'High'}
```

| Fraud probability | Risk level |
|---|---|
| below 0.30 | Low |
| 0.30 to 0.70 | Medium |
| 0.70 and above | High |

The Random Forest model is used. `src/risk_report.py` counts the test transactions per risk level (`reports/risk_summary.csv`, `reports/figures/risk_levels.png`).

## Web dashboard

`dashboard/` is a web dashboard (deployed on Vercel) with a live risk checker, charts and model results.

- `dashboard/public/index.html` is the page, `dashboard/public/data.json` holds the numbers it shows.
- `dashboard/api/predict.js` runs the Random Forest in JavaScript (trees exported to `dashboard/api/_model.json`).
- Environment variables (all optional): `LOW_LIMIT` (default 0.30), `HIGH_LIMIT` (0.70), `MAX_AMOUNT` (1000000), `MODEL_NAME`, `APP_ENV`.
- After retraining, run `python src/export_dashboard.py` to refresh the exported model and numbers.
